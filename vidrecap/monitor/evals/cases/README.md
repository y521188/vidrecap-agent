# 考卷存放说明

本目录放评测集数据，一行一条 JSON（JSONL，UTF-8，LF 换行）。

## scorer_v1.jsonl —— A 层：打分器考卷（已完成，49 条）

一条 = 一句话 + 它的原文上下文 + 标准答案。实际配比：

| category | 含义 | 坏例 | 好句对照 |
|---|---|---|---|
| `clarity` | 缺主语、指代模糊 | 8 | 4 |
| `fluency` | 词语重复、标点连用、碎片、严重连读 | 8 | 4 |
| `completeness` | 被截断、话说一半 | 8 | 4 |
| `mixed` | 以上手法叠加 | 5 | 0 |
| `good` | 好句对照（含"很短但完整""较长但清晰"的对抗性样例） | 0 | 8 |

```json
{"id": "clarity-001", "category": "clarity",
 "context": "主持人分析了媒体融合趋势，并结合案例给出了详细说明。",
 "sentence": "介绍了媒体融合趋势，并结合案例给出了详细说明。",
 "gold": {"passed": false, "note": "缺主语：不知道是谁介绍的"}}
```

`gold.score_range` 字段预留给"更严的期望分数区间"校验，当前不参与判分，一律留空。

**这套考卷要打个折扣看**：出题人与打分规则作者是同一人，所以满分只说明"规则与考卷自洽"，
不代表真实场景的准确率。它的价值在于——一旦改动让质量退步，CI 会立刻拦下；
将来接真实模型打分器时，可以在同一批题上横向比分数。

**已知局限**（有专门的测试锁住，见 `tests/test_quality.py`）：
启发式打分器看不见上下文，短句里出现一次指代就会判低分，哪怕指代实际上很清楚
（例如"他们决定重拍开场。"）。要修它就得引入上下文理解，那是模型档打分器的活。

## corrector_v1.jsonl —— B 层：修正器考卷

一条 = 烂句 + 原文 + 必须保留的实体 + 参考修正。约 15 条。

```json
{"id": "corr-001",
 "context": "第3段：主持人分析了媒体融合趋势，并结合案例给出了详细说明。",
 "sentence": "介绍了媒体融合趋势。",
 "gold": {"passed_after": true,
          "must_keep": ["主持人", "媒体融合趋势"],
          "reference": "主持人分析了媒体融合趋势。",
          "note": "缺主语且信息不全"}}
```

## 出题规矩

1. **坏例写"典型烂"，不写"极端烂"**——打分器是启发式，刁钻到人也要想半天的不算数；
2. **必须有对照好句**——否则"见谁都给低分"的退化实现也能拿高分；
3. **原文要自洽**——`context` 是判断句子是否缺失信息的唯一依据，出题时先想清楚"好句子长什么样"；
4. 类别配比与基线门槛见 `docs/ROADMAP.md` 与 `vidrecap/rules/baselines.py`。
